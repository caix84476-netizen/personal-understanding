# Conflict and Source-Attribution Correction Policy

## Conflict handling (formerly conflict-policy)

When new and old records disagree:

1. Keep both the old and the new raw material;
2. Compare dates, sources, speakers, and context;
3. What the user just explicitly said takes priority;
4. Link the new record to the old one via `supersedes`, `contradicts`, or a correction chain;
5. State the conflict explicitly in the answer — never smooth it over with an average;
6. When it cannot be judged, keep the conditional model and ask.

Conflicts over person attribution, time ordering, and what the user actually meant are high-risk conflicts: they require a deep read-back of the verbatim capture, or an explicit report that the verbatim capture is missing.

## Source attribution and correction (formerly provenance-and-correction-policy)

User verbatim, user evaluations of material, third-party analysis, and model speculation must be kept in separate layers. When the user issues an explicit correction, first capture the full verbatim, then build the correction or supersede chain.

External chats, OCR, screenshots, follow lists, and identically named accounts must not automatically turn an author's analysis into a user fact. Attribution of people, relationships, schools, and accounts must be verified against user statements, time, scene, and readable-back sources.

Regression check after every correction: was the verbatim saved, was the old error demoted to history, were the person connections preserved, did unevidenced identity inference stay un-promoted, and are the relevant context cards reachable?
