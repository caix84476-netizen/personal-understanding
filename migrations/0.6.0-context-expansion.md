# 0.6.0 context expansion migration

Date: 2026-08-14

## Purpose

Fix retrieval treating the single record the model selected as if it were the complete relevant set. Existing records do not need rewriting; old fields stay compatible.

## What changed

- `SKILL.md` and the retrieval policy moved to `survey → seed → contextual probe → deep`;
- `retrieve_context.py --ids` now only means seeds; probe returns compact candidates covering relation neighbors, counter-evidence, conflicts/alternatives, and cross-domain anchors;
- deep automatically loads evidence/conflict/alternative candidates and still reads sources only for already-loaded records;
- `related_ids` are expanded as context candidates but are not proof of facts;
- query-only calls return routing suggestions only, and no longer implicitly treat keyword-hit records as read;
- added `rule.self-distillation.contextual-relevance-expansion-20260814`, recording the archive owner's explicit request for global scanning and multi-thread cross-verification;
- catalog views were rebuilt; structural validation and 61 regression tests passed.

## Compatibility boundary

Raw sources are never rewritten, old state is not deleted, and historical records are still read on demand for timeline/conflict purposes. Candidate expansion has a hard cap; records beyond the cap leave a path and stop reason in `stopped_candidates`, and `--max-context-candidates` widens the range.
