# 机制详解：一条消息在档案里的一生

> 本文回答 README 里所有的「怎么做到」。一条线索走到底：一条消息进来，系统怎么决定收不收（第一节）、怎么原样保存（第二节）、怎么拆成档案（第三节）、怎么在以后被想起来（第四到八节）、以及怎么防止自身出错（第九、十节）。操作契约的唯一事实源是 [SKILL.md](../SKILL.md)；字段级细则在 [references/](../references/) 的 14 份政策文件里，本文按需指路。

## 1. 入口：两档闸门与预检分类

不是每句话都进档案。每条消息先过 **preflight（预检路由）**：一个关键词启发式分类器做初判——

- 第一人称 + 标记词（经历、状态、感受、关系、决定、偏好）触发；
- 强情感词没有「我」字也召回（「有点烦」「挺焦虑的」）；
- 技术语境（python / 代码 / 配置 / 报错等词）否决触发。

判出来两档：**完整档**走全流程；**跳过档**（纯技术、今天吃什么、一次性购物）完全不碰档案——不存证、不捕获、不派生。词表枚举不尽，**兜底责任在模型**：分类器漏了，模型在同一 turn-id 上重声明升级；判错方向宁可多收（确认无新内容后体面关闭，零成本）也不漏收（原话永久丢失）。

活动足迹类消息（「只狼怎么打弦一郎」→ 可沉淀为「正在玩《只狼》」）也走完整档，但受**足迹纪律**约束：写入前必须定向查重、恰好一条微型记录（`tier=light`、权重 0–1）、查重确认完全覆盖就以「无新增」体面关闭，禁止为走流程制造噪声。

细则：[SKILL.md §1 两档调用闸门](../SKILL.md)。

## 2. 原话保真：先存证据，再谈理解

只要消息含个人材料，**先把完整原话一字不改保存，再做任何摘要、拆分、提取或解释**。这是全系统最高优先级的规矩：

- preflight 暂存服务端实际收到的 UTF-8 原文；capture 只传 `capture_id + turn_id` 转正暂存，**不重新手打原文**——保证两次调用之间零转述漂移；
- 每份原话带 `utf8_sha256`、捕获时间、会话标识、来源路径；
- 捕获一旦存在不得覆盖；**纠正只能新增**，旧的留作历史；
- 同一 `conversation_id` 下相同消息哈希复用旧 turn-id——包括已闭环后的重复发言，不会产生重复档案；
- 图片、音频、文件用 `capture_attachment.py` 保留原件并登记哈希，OCR / 转写只是派生物；
- 外部材料（别处聊天记录、手工录入）显式标 `source_kind=external`、`speaker=external`，不能冒充本轮用户说过的话。

保真度分级（`evidence_fidelity`）：`verbatim`（逐字节原话）、`exact_attachment`（原件）、`summary_only`（旧摘要，属迁移债务）。丢了原话的旧记录永远标 `summary_only`，检索会明说「这段来自旧摘要，不是原话」——**绝不从摘要反向编造原句**。

细则：[references/capture-and-verbatim-policy.md](../references/capture-and-verbatim-policy.md)。

## 3. 派生与闭环：从一段原话到档案

capture 成功 ≠ 档案更新完成。每条捕获进入 `memory/derivation-ledger.json` 的 **pending（待派生）** 状态，必须走完派生并以两种方式之一**闭环**：

- `derived`——至少一条 capture ↔ record 双向链接（每条派生记录带 `capture_id` 或 `verbatim_refs` 回链到原话）；
- `no-derivation-needed`——确认无新内容，写明查重命中了哪条具体记录。

仍有 pending 时禁止声称「已录入」。回答前的 **session_check（硬闸门）** 强制校验本轮 receipt、capture、finalize 三件套，缺任一项 fail closed；默认 light 模式只查本轮，毫秒级。

派生拆什么、怎么建模：

- **时间主干**：每条记录留 `date_start/date_end/date_precision/date_basis/phase/salience/entity_refs/before_ids/after_ids`。事件发生日、回忆日、材料写作日、录入日分开记——**禁止把录入当天冒充发生日**。
- **实体档案**：人物、群体、学校组织、地点、物品、书籍作品、游戏影视、概念、生活环境九类。事实只存一份（原话与事件是唯一正本），实体页只是投影；**实体正文不写可变状态**（「在读」「已购」这类断言挂到走版本链的 `state` 记录，否则变成永不更新的僵尸信息）。上下文无法确定的代词不造假人物，挂事件的 `unresolved_referent` 等以后补。
- **情境卡（facet）**：解决「学校 × 足球」式交叉——多个实体在同一事件/空间/关系/体验里共现才开卡，卡片只放共同入口，不复制内容；偶然共现不写因果。
- **因果假设**：用户问「我为什么总是这样」时的模型猜测，独立一层，必须带 `claim / mechanism / supports / contradicts / alternatives / scope / confidence` 七要素，状态恒为 `candidate`——至少两条支持证据，找不到反例要明说「反例缺失」，**永不转正成事实**。
- **待回访**：「等几天看结果」「对方还没回复」这类开放闭环，带 `due_at` 与上下文入档；每次运行先查到期项，到期主动回访且必须带完整背景（「你在某日提到……当时约定……后来怎么样？」），禁止没头没尾突然追问。

细则：[references/architecture-v2.md](../references/architecture-v2.md)、[entity-and-context-policy.md](../references/entity-and-context-policy.md)、[timeline-and-followup-policy.md](../references/timeline-and-followup-policy.md)、[causal-hypothesis-policy.md](../references/causal-hypothesis-policy.md)、[conflict-and-correction-policy.md](../references/conflict-and-correction-policy.md)。

## 4. 记忆权重与事实层级

权重只有一根轴：**salience 0–3**——`3 主轴`（改变长期理解）、`2 关键`（改变某条生活线）、`1 关联`（背景与连接）、`0 提及`。`entry_kind` 表示「这是什么」，与权重是两回事。

事实分五层，永远分层摆放：① 用户原话事实 → ② 用户对材料的评价 → ③ 用户自己的解释 → ④ 模型候选解释（只能进假设层）→ ⑤ 无法确认（留来源和缺口，不凭空补全）。新内容优先于旧档案，但旧事实不静默擦除——建 `supersedes` / `contradicts` 纠正链，回答时必须明说冲突，**不许取平均和稀泥**。

细则：[SKILL.md §4 事实层级与记忆权重](../SKILL.md)。

## 5. survey / probe / deep：三层渐进检索

检索的核心纪律：**不把全库灌给模型**。五类读取各带字符预算与确定性截断，超预算输出合法 JSON 并附 truncated 元数据：

| 层 | 预算 | 干什么 |
|---|---|---|
| `survey` | 48K | 紧凑路由地图：时间主干、当前状态、实体/情境卡/假设目录、待回访、资料缺口。回答「我在哪、该往哪找」。时间主干按人生阶段分桶取样，早期关键事件不会被新条目挤出地图 |
| `routing` | 68K | 按领域展开目录（`--query` 定向） |
| `full` | 96K | 完整目录 |
| `probe` | 80K | 选入口（事件/实体/情境卡/状态/待回访/假设）读派生卡片并扩展：时间邻居、涉及实体、共同情境卡、支持/反驳/替代/supersede 关系。**probe 永远不读原话全文** |
| `deep` | 100K | 只在需要精确事实、时间、归属、矛盾、原意时，读选中条目的原话片段；旧摘要在 deep 阶段不能伪装成原文 |

probe 的契约输入是**模型自己提取的关键词**（整句直查只在 routing/时间窗场景合法）。每条时间条目带 `evidence_fidelity` 保真计数；每次检索的决策轨迹（用了什么词、选中哪些 ID、什么被预算截断）持久化到 `memory/v2/traces/`，漏召回时可逐段回放定位。

**工具与模型的分工**：工具负责把召回体力活做厚——候选捞全、宁滥勿漏；判断与拍板永远在模型。前排有噪声不静默吞下，按 trace 向用户说明「为什么出现、为什么不采信」。

细则：[references/retrieval-policy.md](../references/retrieval-policy.md)、[retrieval-decision-trace.md](../references/retrieval-decision-trace.md)。

## 6. 联想通道（发散）：词面对不上的怎么想起来

词面检索有一个死穴：你说「打击感跟纸糊的一样」，档案里记的是「巫师3 骑马手感稀烂」——零词面重叠，两头不靠。**联想通道（associations）** 就是治这个的，作为 probe 输出里的独立段落存在：

- **算法**：个性化 PageRank（PPR）在档案图（记录—实体—概念卡）上做 **4 次迭代的局部扩散**；种子 = 本轮查询命中的实体/概念卡。
- **两级候选**：种子实体投影（图距离 1 的自有记录，按 salience 排序）+ 图扩散邻居。
- **概念卡是地基**：`entity.concept.*` 抽象层节点，aliases 覆盖口语入口词（「书荒」「晕3D」「考公」「史低」「打击感」）——没有概念卡时，实测的「联想」只是共现随机游走。
- **输出契约**：每条带 `via_entity` 路径与 `spread_score`，可审计可回放；**它是候选池不是排序结果**——模型自己判断联想成立才引用，绝不混入 timeline，也绝不自行构成入选资格。

词面管精确回忆，图管发散联想，两条通道证据链各自可见。

## 7. 聚合读法（侦探拼图）与逆向冷回溯

**聚合读法**——宽泛决策问题（「我该怎么办」「我是个什么样的人」）拆 2–4 个 probe：情绪线、利益线、人物线各一发，用该线的足迹关键词；跨域收集各线前排 + associations 强候选 + entities 段命中的卡片，再对直接相关记录用 `ids` 精读核原话。回答分三层：**档案事实 / 模式观察 / 模型推断**，推断注明依据哪几条记录；禁止把单次事件升格为人格定论。

**冷回溯**——用户「想不起关键词」时的阶梯：

1. 从已提到的任何人物/地点/物品/时间线索 probe，顺实体发散；
2. 命中后沿 `before_ids/after_ids` 时间邻居前后走；
3. 仍无命中，用 `retrieve_v2.py --window 2025-03`（或 `起:止`）按时间窗浏览标题，让用户自己认领；
4. 时间也说不准，就按 phase 逐段扫时间主轴。

**禁止宣布「查不到」**——只换路，不结案。被降权到 salience 0 的记录在这三条路径上依然可达。

## 8. 词面层：让中文查询不被切烂

检索的底座是一套词元净化层（`scripts/lexicon.py`）：

- **词典**：vendor jieba 词典（34.9 万词条）+ **档案自训练词表**——从档案文本挖 DF≥2 的 2–4 字字段 + 全部实体卡 label/aliases，重建视图时自动刷新。档案自身就是最懂自己专名的词典。
- **三类实测修复**：① ASCII 单字符不再有内容词资格（「巫师3」拆出的「3」曾让驾照记录霸榜）；② CJK/ASCII 边界的混写专名自动粘连成整词（「巫师3」「晕3D」不被切碎）；③ 词典外切片权重 ×0.4 封顶——保留召回但失去虚高 IDF（第一版「直接删除」立即误杀只在档案出现 1 次的「弦一郎」，改降权后零误杀）。
- **加权打分**：IDF（稀有词高权）、单字近零权、拉丁专名加码、长度归一。
- **锚定比值降权**：整句口语查询切出的跨词假 n-gram（「郎我」「卡了」）在小语料上 df≈1、拿满 IDF 霸榜——修复为记录得分乘以「该记录命中的最强词重 ÷ 查询最强词重」。
- **时间衰减**：词面得分 ×0.5^(age/180d)；**缺日期记录中性 1.0**——按「极旧」处理会无声埋掉 9% 无日期事件的正确记录（实测踩出）。
- **版本化事实**：被 supersede 的旧行软降权 ×0.5——行仍可见、带状态供讲版本链，只动顺序，绝不过滤。

## 9. 质量回路：反馈、复盘、审查、备份

- **反馈回路**：依赖档案的回答被用户明确纠正/确认/说「不对」时，记 helpful / missed / corrected / unclear，note 必须引用当时原话作证据。**默认是不记**——沉默、换话题、简短回复都不是信号，防止模型给自己的作业打分。`corrected` 是唯一驱动行动的信号：深度审查把「最常被纠正的记忆」列为优先检查项。
- **季度权重复盘**：档案只增不减，权重会漂移。`salience_review.py` 列出 180 天以上未再确认、权重来自导入启发式的记录，降为 `salience: 0`（保留、可检索、退出活跃地图）——不删除、不改内容；用户自己评过权重的一律不动。
- **语义审查**：`review_v2.py --deep` 扫原话与事件一致性、归属正确性、时间顺序混淆、事实/感受/解释/假设混层、旧摘要冒充原话、假设证据缺口。审查能报告「无法核验」，**不能凭空补写**。
- **三态校验**：`validate_memory.py` 输出 clean / warnings / failed，内嵌派生台账审计（孤立捕获、链接漂移）。
- **备份与恢复**：工作档案是活的预览版；归档快照（stable + previous 两代，SHA-256 清单）只在「跑了 7 天以上且结构校验通过」时刷新——「表现正常」才是快照标准，不是「没变化」。恢复走 `restore_stable.py` 范围恢复（code / data / all，dry-run 默认，恢复前自动快照可回滚）。另有热镜像看门狗：检测到大规模删除（存活文件跌破镜像 60%）时自动从镜像还原。

细则：[references/review-and-feedback-loops.md](../references/review-and-feedback-loops.md)、[maintenance-and-durability.md](../references/maintenance-and-durability.md)。

## 10. 诚实边界与防过拟合

贯穿全系统的几条红线：

- 不确定就说不知道；禁止宣布「查不到」，也禁止编一个补上。
- 「档案里没有 X」是需要证据的断言——说出口前必须先对 X 做定向 probe，空手才许出口；标题、目录、直觉印象都不算证据。
- 任何「用户当前处于某阶段」的断言，输出前必须拿当前日期与档案显式对照；对不上就只能问或说不知道。**先对日期，再讲故事**。
- 因果假设、推断、猜测永远带身份标签，不冒充事实；单次事件不生成稳定因果。
- 修复常量（门控阈值、迭代数、衰减周期、降权系数）按批次行为调，**不对单条查询调参**；冻结回归套件只作地板不作优化目标；每轮验收换全新试卷。行为实验零收益的提案（如 PMI 词表内聚过滤）否决留档，不合入。
- 隐私：相关性是唯一读取开关——会改变答案才读敏感内容；无关问题不主动泄露；但档案写出来就是给模型看的，因怕泄露而少接触数据是本末倒置。
